CMB1498 - switch to hoverbike_02, and stop matching rig parts by exact name

The rev-02 export is clean: handle_bars rotates -15/+15 deg with ZERO translation on both sides, so
the left-turn bar slide is fixed at the source. The rotation-only pin from CMB1497 stays as a
guard - it now finds only 7 values to correct on this export, down from 70 on rev 01.

Switching to it would have silently broken two things, and both were the SAME mistake: identifying
rig parts by an exact string that an exporter is free to change.

  turn clips  'left'/'right'  ->  'left turn'/'right_turn'   (space vs underscore, inconsistently)
  grip nodes  hand_grip_l/r   ->  left_hand/right_hand

Neither miss throws. The clip lookup would return undefined and the bars would simply never turn;
the grip lookup would return undefined and the hands would quietly stop reaching the bars. Both are
now matched by MEANING - any clip containing left/right is that turn take, whatever contains
neither is the neutral take; a grip is a hand/grip node that has a side. 'handlebars' contains
'hand' but has no side, so it can never be mistaken for a grip. Both exports resolve correctly.

Verified on the new rig in-game:
  fit           22 x 22.3 x 47
  turn clips    resolved as 'left turn' / 'right_turn'
  steering pose LEFT and RIGHT handle_bars position identical, quaternions exact mirrors (+/-0.131)
  grips         left_hand / right_hand, symmetric about the bike centreline
  muzzles       2, symmetric, forward
  jets          4, symmetric, at the tail - exhaust confirmed on screenshots
  seated + flight both confirmed on screenshots

window._BIKE_GLB still accepts a path, so the old export can be A/B'd live.
